# Paper Reconstruction v2.0.5 - CPU capture alignment recovery

Stage 4 recovers rotations missing from the upstream pose bank and repairs supported but misaligned assemblies using observed borders, verified native seams, fixed-scale rigid refinement and placed-tree-cut repair. The solver source is the exact implementation qualified by the v2.0.4 development runs: fingerprint `6000dccca2004995b02a6b76f21791e5a85b1daabfd235cb755be4761fb69c37`.

All **14 cold development regressions pass through 30 pieces**: 228 pieces, zero false selected neighbor pairs and a largest saved-probe displacement of 30 native pixels. Independent native support, physical checks, prediction seals and every preview were reviewed. The cold **six-piece real-capture reconstruction succeeds in 486.8 seconds (8m7s) on CPU**, without previous assembly or reference poses. Post-seal registration measures approximately 3-9 native pixels of per-piece contour p95 displacement. All eight selected joins verify independently; relative scale remains exactly 1.0.

GitHub CI for the initial v2.0.4 tag passed the complete solver suite and CPU ranker checks on Windows/Linux, but found a path-alias assertion in a new runner test: Windows short and full temp-directory names were compared textually. This patch canonicalizes both paths in that test. Production solver code, models, SDK and benchmark results are unchanged. The v2.0.4 tag is preserved; v2.0.5 is the release containing the portability-test correction.

Validation includes **362 Stage 4 tests passed**, 16 documented historical skips, **19 portable pipeline/runner tests passed**, four-stage source/model compatibility and export verification. CPU remains the default. Stage 1-3 and all four frozen Git LFS weights are unchanged. Saved Stage 2/3 banks remain compatible; no upstream regeneration is required for Stage 4-only testing.

The new cold capture runner freezes source, reports progress, refuses previous-assembly inputs and seals predictions before separate assessment. See [capture commands](https://github.com/DanielKatzman/paper-reconstruction-stage4/blob/v2.0.5/docs/CAPTURE_QUALITY_RECOVERY.md), [alignment and regression review](https://github.com/DanielKatzman/paper-reconstruction-stage4/blob/v2.0.5/docs/V204_CAPTURE_ALIGNMENT_REVIEW.md) and [Stage 3 handoff](https://github.com/DanielKatzman/paper-reconstruction-stage4/blob/v2.0.5/docs/STAGE3_HANDOFF.md).

The real case is one development page, not a 30-piece real-photo reliability claim or a fresh end-to-end pipeline timing. Raw real images, masks, poses and previews remain local. Geometry score is not an accuracy probability; reference measurements occur only after prediction sealing. All earlier tags remain intact.

The model/data baseline remains v2.0.0: [models](https://github.com/DanielKatzman/paper-reconstruction-stage4/releases/download/v2.0.0/models-v2.0.0.zip), [benchmark](https://github.com/DanielKatzman/paper-reconstruction-stage4/releases/download/v2.0.0/benchmark-v2.0.0.zip), [checksums](https://github.com/DanielKatzman/paper-reconstruction-stage4/releases/download/v2.0.0/checksums.json).
