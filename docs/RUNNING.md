# Runtime and asset setup

Use separate interpreters: Stage 1/2 use Python 3.14; Stage 3/4 use Python 3.12. Version 2.0.1 installs CPU-only Torch 2.7.1 for Stage 3 by default. The historical 2.0.0 preparation used Torch 2.7.1+cu118; its device is recorded in the original receipts. Stage 1/2 use CPU ONNX Runtime; Stage 4 uses CPU NumPy/SciPy/Pillow and the SDK. Existing component constraints are retained. `local/runtimes.json` maps stages to interpreters and is ignored by Git. Each subprocess imports inlined source through an explicit `PYTHONPATH`.

`tools/setup.ps1` creates environments under ignored `local/envs` and installs editable components. Its default `-Device cpu` selects `https://download.pytorch.org/whl/cpu` and verifies `torch.version.cuda` is absent and all frozen ranker tensors are on CPU. `-Device cuda` selects the original CUDA 11.8 index; the pipeline still needs an explicit `--device cuda`. Installation needs package-index access. Other systems can install the same packages and supply an interpreter mapping; broad OS and real-capture qualification remain separate from the recorded baseline.

The four release models are tracked with Git LFS; clone after `git lfs install`, then run `git lfs pull`. `compatibility.json` pins the complete stage/model combination. `tools/verify_compatibility.py` verifies component metadata and model sizes/hashes before setup. It fails clearly if only LFS pointers are present. Build-generated `.egg-info` metadata is excluded from source identity checks because installation regenerates it; original package source remains byte-pinned.

`provenance/assets.json` lists models, benchmark inputs, saved evidence bundles, evaluation references and optional original predictions by size and SHA-256. `tools/assets.py verify --groups models bundles inputs references` checks serving/evaluation assets. Original predictions are an optional additional group, never an initialization seed. Private source-page collections, unrelated training checkpoints/datasets, environments and historical output trees remain in the original projects.

`tools/package_assets.py` makes `models-v2.0.0.zip`, `benchmark-v2.0.0.zip` and checksums under ignored `local/release-assets`. The model archive contains the same two ONNX networks and two small Torch rankers as Git LFS and is a fallback for source-ZIP users. Both archives are release downloads; extract them at the repository root and validate before running. The benchmark archive is optional for inference on new inputs and required to reproduce the saved fourteen-case regression.

The new `pipeline.py` requires a fresh output folder. On failure, logs and committed Stage 3 caches remain available for diagnosis; automatic inference continuation/resume is not implemented in this portable umbrella runner. If only post-seal evaluation needs to be repeated, use `python -B tools/pipeline.py evaluate --run outputs/<run>`; it authenticates the prediction barrier before opening references and preserves prediction files. Original Stage 3 and Stage 4 component CLIs retain their own validated resume policies. `--resume` on the historical experimental controllers is not a replacement for the portable commands.

The default development route requires an existing Stage 1 folder with `segmentation_manifest.jsonl` and a bound `capture_profile.json`. It reruns Stage 2/verification, Stage 3 native inference/pooling and Stage 4. The source Stage 1 generator is included at `stages/stage1/src/universal_segmenter/generation`; its original training data and source PDFs are optional private inputs. The exact benchmark inputs are preserved as assets, so regeneration is not required to reproduce the saved cohort.

For a capture folder, use `--captures`, `--mode shared-scale-capture` and an explicit `--capture-profile`. Stage 1 runs with its calibrated model and selected review mode. The profile declares common native scale, no per-piece resizing and no perspective. Version 2.0.2 uses V21 with `shared_scale_complete_rectangle_predicted_v1.json`; generator inputs keep the exact-mask profile. Physical scale 1.0 is independent of mask error or placement precision. Unknown rotation under a proper-rigid capture declaration selects observed-angle native fitting, not an assumed quarter-turn acquisition.

Raw model outputs remain under `stage1_native`; `stage1` is the audited downstream copy. A bounded mask adapter reconciles diagonal fringe pixels with Stage 2's four-connectivity requirement, without resizing or altering the raw output. It rejects meaningful fragment removal instead of silently changing the piece. The receipt is `stage1/mask_boundary_adapter.json` and its subprocess log is `stage1_boundary.log`.

Generated result JSON includes status, selected layouts and complete diagnostics; a subprocess exit code of zero only means it published normally. A partial or unsupported layout is not a successful reconstruction. The benchmark review requires supported status, connectivity, no false selected neighbors, complete inventory and common-gauge measurements. Its explicit offline regression policy allows up to 48 native pixels maximum saved-probe displacement, relative orientation error at most 0.001 degrees and scale error at most 0.00001. This protects against a wrong/scaled/far-displaced piece hiding behind correct neighbor IDs; it does not change serving gates or certify unseen-page reliability. Four-pixel exactness remains a diagnostic. Preview review is still required.
