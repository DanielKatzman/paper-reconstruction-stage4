# Paper Reconstruction v2.0.4 - CPU capture alignment recovery

Stage 4 now recovers rotations missing from the upstream pose bank and repairs supported but misaligned complete assemblies. Long observed border spans suggest rotation hypotheses; native curved seam fitting, independent support replay, collision and complete-page checks decide whether they can be used. Local rigid refinement and tree-cut repair keep relative piece scale exactly 1.0. Acceptance thresholds are unchanged.

The cold six-piece real-capture test now reconstructs a coherent page in **486.8 seconds (8m7s) on CPU**, using the saved CPU-produced Stage 2/3 evidence with no previous assembly or reference poses. All eight selected joins verify independently. Post-seal reference registration measures approximately 3-9 native pixels of per-piece contour displacement (p95), compared with about 211 pixels for the previously misplaced corner. Page geometry score is 0.9953; it is a shape score, not an accuracy probability. The original page is used only for post-run measurement. Raw real images, masks, poses and previews remain local.

All **14 cold development regression puzzles pass**, two each at 4, 8, 12, 16, 20, 24 and 30 pieces (228 pieces). Every selected layout is supported and connected, with zero false selected neighbor pairs. The largest saved-probe displacement remains 30 native pixels, with no relative orientation or scale errors. Independent review replays native support and physical checks from each immutable upstream bundle and verifies every prediction seal.

Local validation: **362 Stage 4 tests passed**, 16 documented historical skips, and **19 portable pipeline/runner tests passed**. CPU remains the default. Stage 1-3 source, the SDK and all four Git LFS model files are unchanged from v2.0.3. Existing Stage 2/3 banks remain compatible; no regeneration is needed for the Stage 4 regression.

The new cold capture runner freezes Stage 4 and SDK source, reports progress, refuses old assembly seeds and nonempty output directories, and seals predictions before independent assessment. See [running capture recovery](https://github.com/DanielKatzman/paper-reconstruction-stage4/blob/v2.0.4/docs/CAPTURE_QUALITY_RECOVERY.md), [validation details](https://github.com/DanielKatzman/paper-reconstruction-stage4/blob/v2.0.4/docs/V204_CAPTURE_ALIGNMENT_REVIEW.md) and [Stage 3 feedback](https://github.com/DanielKatzman/paper-reconstruction-stage4/blob/v2.0.4/docs/STAGE3_HANDOFF.md).

This is one real development page and an existing development cohort, not a held-out reliability claim, a 30-piece real-photo qualification or a fresh end-to-end timing. The API, GUI and container orchestration remain planned work. All earlier release tags are preserved.

Models and benchmark inputs use the unchanged v2.0.0 asset baseline: [models](https://github.com/DanielKatzman/paper-reconstruction-stage4/releases/download/v2.0.0/models-v2.0.0.zip), [benchmark](https://github.com/DanielKatzman/paper-reconstruction-stage4/releases/download/v2.0.0/benchmark-v2.0.0.zip), [checksums](https://github.com/DanielKatzman/paper-reconstruction-stage4/releases/download/v2.0.0/checksums.json). Git LFS obtains the same four pinned weights with this source tag.
